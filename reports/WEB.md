# Веб-интерфейс: проверка 27 октября 2026

На момент проверки интерфейс работал по адресу `http://195.70.199.18:8080/`. По умолчанию был выбран
полный индекс `data/index-full`.

## Реализация

- `search_engine serve` запускает HTTP-сервер на C++. Несколько постоянных рабочих потоков
  обрабатывают запросы; размер очереди ограничен. Индексы открываются по мере необходимости и
  остаются открытыми. Для поиска используются `QueryParser` и `QueryExecutor`.
- `web/index.html`, `web/app.css`, `web/app.js` содержат браузерный интерфейс. Для его запуска не
  нужны npm-пакеты, отдельная сборка или загрузка файлов со сторонних серверов. Доступны поиск,
  выбор индекса и алгоритма, переход между страницами выдачи, подсветка целых слов и чтение полей
  `title`, `headings`, `body`. Поддерживается узкий экран.
- Полный документ читается из исходного корпуса по `docid`. Для официального tar-архива программа
  находит нужный gzip-файл и строку по смещению в распакованных данных. Для других корпусов
  используется `CorpusReader`. Прочитанный документ сохраняется на диске для повторных обращений;
  текущая страница сайта по URL не загружается.
- `scripts/run_web.sh` запускает сервер в терминале. `scripts/web_server.sh start|stop|status`
  управляет отдельным фоновым процессом, который продолжает работать после закрытия SSH. После
  перезагрузки сервера его нужно запустить снова.

## Проверки

- Исправлен повторный запуск при устаревшем файле с номером процесса (PID): восстановлен номер
  действующего сервера 3439279 без его остановки. Команды управления выполняются по одной, а номер
  нового процесса записывается после того, как сервер занял порт и начал отвечать.
  [Отдельный тест](tests-web-lifecycle.txt) проверяет одновременные старты, повторный старт,
  восстановление отсутствующего или устаревшего PID и остановку на отдельном порту.
- В сборке Release прошли все 3 набора CTest: [журнал](tests-web-release.txt).
- С проверками памяти и недопустимых операций ASan/UBSan прошли все 3 набора CTest:
  [журнал](tests-web-sanitize.txt).
- Дополнительные HTTP-проверки для tar/gzip прошли в [Release](tests-web-api-release.txt) и
  [сборке с ASan/UBSan](tests-web-api-sanitize.txt). Проверены документ длиннее 128 КиБ, чтение по
  смещению из docid, следующий документ и gzip-файл из нескольких последовательно сжатых частей.
- Проверены полный `body` при коротком сохранённом фрагменте начала текста, Unicode, пустое значение
  `null` в headings, оба выражения с вложенным `ANDNOT`, переход между страницами выдачи,
  неизвестные индексы и документы, неверные параметры и повторное чтение сохранённой копии.
- В Chromium проверены поиск и поля документа, точная подсветка (`model` не выделяется внутри
  `models`), переключение алгоритма и индекса, переходы вперёд и назад, ошибки в запросах и экран
  шириной 390 пикселей без горизонтальной прокрутки. HTML из документа показывается как текст,
  ссылки `javascript:` не открываются. [Журнал](tests-web-browser.txt). Проверка через адрес сервера
  выполнялась без прокси, заданного в окружении.
- Прямой запрос к `195.70.199.18:8080` вернул HTTP 200, а `/healthz` — `{"status":"ok"}`. Основной
  сервер оставлен работающим; вспомогательный сервер тестового корпуса остановлен.

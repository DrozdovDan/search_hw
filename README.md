# MS MARCO Search

Поисковая система на C++20 для документов MS MARCO v2. Она строит инвертированный индекс — таблицу,
которая для каждого слова хранит список документов с этим словом. Поиск поддерживает условия `AND`,
`OR`, `ANDNOT`; найденные документы можно читать в браузере.

При построении документы читаются по очереди, а индекс накапливается частями. Эти части называются
сегментами: каждая записывается на диск, затем они объединяются. Для поиска используется `mmap`:
программа обращается к байтам файлов через адреса памяти, а операционная система подгружает нужные
данные.

## Возможности

- Индексирование `title`, `headings` и `body` с поиском по отдельным полям.
- Чтение JSONL, gzip, tar и каталогов без предварительной распаковки всего корпуса.
- Параллельный анализ текста с сохранением исходного порядка документов.
- Два способа перехода по спискам документов: последовательный просмотр или экспоненциальный поиск с
  последующим бинарным.
- Разовые запросы из командной строки, интерактивный режим и веб-интерфейс с полным текстом и
  фрагментами вокруг найденных слов.

Документы возвращаются по возрастанию внутренних номеров. Программа не оценивает их смысловую
близость к запросу. Разные формы слова не приводятся к общей основе: `machine` и `machines`
различаются. Позиции слов и сжатие списков документов не реализованы.

## Сборка

Требуются Linux x86-64, компилятор C++20, CMake 3.20 или новее, zlib, ICU и pthreads. Библиотека для
разбора JSON nlohmann/json включена в `third_party/`; сведения о лицензии находятся в
[описании зависимости](third_party/README.md).

Для Ubuntu:

```bash
sudo apt-get install build-essential cmake zlib1g-dev libicu-dev curl wget ripgrep
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j 8
ctest --test-dir build --output-on-failure
```

Сборка с ASan/UBSan и дополнительные проверки описаны в
[руководстве разработчика](docs/DEVELOPMENT.md).

## Быстрый запуск

Для проверки не нужен полный MS MARCO. Можно создать небольшой корпус:

```bash
./build/search_engine generate --output data/demo.jsonl --documents 10000 --seed 42
./build/search_engine index \
  --corpus data/demo.jsonl \
  --output data/demo-index \
  --threads 4 \
  --memory-limit-mb 64
./build/search_engine interactive --index data/demo-index
```

В интерактивной сессии вводите по одному запросу на строку:

```text
machine AND learning
(machine OR python) ANDNOT model
title:python AND body:learning
:quit
```

Индекс создаётся один раз и сохраняется на диске. Для повторного построения задайте новый каталог
`--output`: существующий индекс не перезаписывается.

## Работа с MS MARCO

Используется набор полных документов MS MARCO v2: 11 959 635 документов в архиве
`msmarco_v2_doc.tar`. Описание данных и контрольная сумма опубликованы в
[репозитории Microsoft](https://github.com/microsoft/msmarco/blob/master/TREC-Deep-Learning-2021.md#document-ranking-dataset).

Загрузить корпус и построить индекс первых 50 тысяч документов:

```bash
./scripts/download_corpus.sh data/msmarco_v2_doc.tar
./build/search_engine index \
  --corpus data/msmarco_v2_doc.tar \
  --output data/index-50k \
  --max-docs 50000 \
  --threads 8 \
  --memory-limit-mb 512 \
  --snippet-bytes 240
```

Для полного корпуса уберите `--max-docs` и выберите новый каталог назначения. Примеры, параметры
памяти и порядок проверки архива приведены в [руководстве по запуску](docs/USAGE.md).

## Поиск из командной строки

```bash
./build/search_engine search \
  --index data/index-50k \
  --query 'machine ANDNOT (python OR model)' \
  --top-k 10
```

Результаты печатаются в формате JSONL: одна строка JSON на документ. В ней находятся внутренний
номер, исходный `docid`, заголовок, URL и сохранённый фрагмент начала текста. `AND` и `ANDNOT` имеют
одинаковый приоритет, выше `OR`. Скобки меняют порядок операций. Между словами нужна явная операция;
операторы пишутся заглавными буквами.

По умолчанию `advance()` использует экспоненциальный поиск, затем бинарный. Для последовательного
просмотра укажите `--advance sequential`.

## Веб-интерфейс

```bash
SEARCH_INDEX=data/index-50k ./scripts/web_server.sh start
./scripts/web_server.sh status
```

Откройте `http://<адрес-сервера>:8080`. Интерфейс показывает результаты, контекстные фрагменты и
полные поля `title`, `headings`, `body` из исходного корпуса. В тексте есть подсветка и переход
между совпадениями.

Полный текст берётся из сохранённого MS MARCO, поэтому он может отличаться от действующего сайта.
Если документ расположен ближе к концу сжатого файла, его первое чтение может занять несколько
секунд. Полученный текст сохраняется в кэше — копии для повторных обращений.

Остановить сервер:

```bash
./scripts/web_server.sh stop
```

Настройка порта, SSH-туннель и работа с уже запущенным процессом описаны в
[руководстве по веб-интерфейсу](docs/WEB.md).

## Где читать код

| Файл                                 | Задача                                                |
| ------------------------------------ | ----------------------------------------------------- |
| [src/corpus.cpp](src/corpus.cpp)     | Потоковое чтение и проверка документов                |
| [src/analyzer.cpp](src/analyzer.cpp) | Выделение слов Unicode и объединение повторов         |
| [src/index.cpp](src/index.cpp)       | Учёт памяти, сегменты, их объединение и обход списков |
| [src/storage.cpp](src/storage.cpp)   | Формат файлов, `mmap` и сведения о документах         |
| [src/query.cpp](src/query.cpp)       | Разбор запросов и получение результатов по одному     |
| [src/web.cpp](src/web.cpp)           | HTTP-запросы и чтение исходного текста                |

В [обзоре кода индекса](docs/INDEX_GUIDE.md) объясняется, почему запись списка занимает пять байт,
как сохраняется порядок номеров при параллельном анализе, когда сегмент записывается на диск и
почему объединение сегментов обходится без повторной сортировки всех номеров.

| Время построения             |    42 мин 1 с |
| Максимальная память процесса |      6,41 ГиБ |

Это результаты конкретного запуска на сервере, где выполнялись и другие задачи. Параметры
оборудования, методика, сравнение алгоритмов и исходные отчёты находятся в
[reports/RESULTS.md](reports/RESULTS.md). Параметр памяти при построении ограничивает структуры
текущего сегмента. Дополнительная память нужна разбору документов, рабочим потокам и библиотекам,
поэтому весь процесс может занимать больше.

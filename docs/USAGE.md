# Запуск и работа с запросами

Команды ниже выполняются из корня проекта после [сборки](../README.md#сборка). Справка по всем
режимам доступна через `./build/search_engine --help`.

## Загрузка корпуса

Нужен MS MARCO v2 Documents — набор полных документов с полями `docid`, `url`, `title`, `headings` и
`body`. В JSONL каждый документ записан отдельной строкой JSON. MS MARCO Passages содержит отдельные
фрагменты текста, устроен иначе и не подходит.

```bash
./scripts/download_corpus.sh data/msmarco_v2_doc.tar
```

Загрузчик продолжает незавершённое скачивание и проверяет MD5 готового файла. Если корректный архив
уже существует, повторная загрузка пропускается.

| Параметр архива | Значение                           |
| --------------- | ---------------------------------- |
| Размер          | 34 648 862 720 байт                |
| MD5             | `eea90100409a254fdb157b8e4e349deb` |
| Содержимое      | 60 gzip-файлов с JSONL             |

Проверить архив отдельно:

```bash
printf 'eea90100409a254fdb157b8e4e349deb  data/msmarco_v2_doc.tar\n' | md5sum -c
```

Если обычная загрузка не работает, можно скачивать части файла параллельно с помощью HTTP-заголовка
`Range`:

```bash
./scripts/download_parallel.sh data/msmarco_v2_doc.tar 32
```

При необходимости прямого соединения без прокси задайте `DOWNLOAD_DIRECT=1`. Сценарий проверяет
диапазоны ответов, сохраняет недокачанные части и сверяет MD5 после сборки. Части остаются в
каталоге `*.parts/`; на время сборки нужно место для них и для итогового архива. Два загрузчика для
одного пути одновременно запускать не следует.

Во время первоначальной загрузки AzCopy 10.34.1 отправлял `x-ms-range`, который сервер загрузки
игнорировал. Запасной сценарий использует обычный `Range`. Это описание конкретного запуска; текущая
работа проекта от AzCopy не зависит.

## Построение индекса

Первые 50 тысяч документов с сохранением короткого фрагмента начала текста:

```bash
./build/search_engine index \
  --corpus data/msmarco_v2_doc.tar \
  --output data/index-50k \
  --max-docs 50000 \
  --threads 8 \
  --memory-limit-mb 512 \
  --snippet-bytes 240
```

Полный корпус:

```bash
./build/search_engine index \
  --corpus data/msmarco_v2_doc.tar \
  --output data/index-full \
  --threads 8 \
  --memory-limit-mb 8192 \
  --merge-fan-in 8
```

`--output` должен указывать на новый каталог. Если индекс уже построен, откройте его для поиска или
выберите другое место назначения.

| Параметр            | По умолчанию | Назначение                                                   |
| ------------------- | -----------: | ------------------------------------------------------------ |
| `--max-docs`        |            0 | Ограничение числа документов; 0 означает весь корпус         |
| `--preset`          |            — | Один из `10k`, `100k`, `1m`, `full`; заменяет `--max-docs`   |
| `--threads`         |            1 | Число потоков анализа текста, от 1 до 256                    |
| `--memory-limit-mb` |          512 | Объём памяти для построения в МиБ, минимум 8                 |
| `--merge-fan-in`    |           16 | Сколько сегментов можно объединять за один раз, от 2 до 64   |
| `--segment-docs`    |            0 | Дополнительный предел документов в сегменте; 0 отключает его |
| `--snippet-bytes`   |            0 | Сколько байт начала `body` сохранить, максимум 65 536        |

`--max-docs` и `--preset` одновременно не задаются. Чтение, анализ и заполнение индекса выполняются
одновременно в разных потоках. Помимо потоков анализа есть один поток чтения и основной поток,
который добавляет результаты в индекс. `--threads 8` не делит архив на восемь равных частей.

75% заданного объёма выделено структурам текущего сегмента. Остальное служит запасом для других нужд
построения. Память на разбор JSON, рабочие потоки и служебные данные также занимает место. Поэтому
фактический объём памяти всего процесса, измеряемый показателем RSS, может превысить
`--memory-limit-mb`. Подробности — в [описании архитектуры](ARCHITECTURE.md).

Индексатор принимает JSONL, gzip, tar или каталог с файлами корпуса. Он проверяет кодировку UTF-8,
нужные поля JSON, заголовки tar и корректность прочитанных gzip-данных. Строка JSONL ограничена 64
МиБ. При `--max-docs` непрочитанный хвост gzip не проверяется, поэтому MD5 официального архива
следует проверить перед построением индекса первых N документов.

## Поиск

Один запрос:

```bash
./build/search_engine search \
  --index data/index-50k \
  --query '(machine OR python) AND learning' \
  --top-k 10
```

Несколько запросов в одной сессии:

```bash
./build/search_engine interactive --index data/index-50k
```

Вводите по одному выражению на строку. `:quit` завершает работу. После ошибки в запросе можно
вводить следующий: индекс остаётся открытым.

| Выражение                         | Условие                                   |
| --------------------------------- | ----------------------------------------- |
| `machine AND learning`            | Есть оба слова                            |
| `machine OR learning`             | Есть хотя бы одно слово                   |
| `machine ANDNOT python`           | Есть machine, нет python                  |
| `title:python`                    | Python встречается в заголовке            |
| `title:machine AND body:learning` | Каждое слово встречается в указанном поле |

Операторы пишутся заглавными буквами. `AND` и `ANDNOT` имеют одинаковый приоритет, выше `OR`; при
равном приоритете вычисление идёт слева направо. Скобки задают другой порядок.

`machine ANDNOT (python OR model)` исключает документы с любым из двух слов.
`machine ANDNOT (python ANDNOT model)` исключает только документы, где есть python и нет model.
Поэтому одна страница может подходить под оба выражения, хотя полная выдача различается.

Поиск работает по целым словам: `model` и `models` различаются. Между словами обязательно указывать
операцию. Поиск фразы и отдельное условие `NOT word` не поддерживаются. Полные правила запросов и
обработки текста описаны в [архитектуре](ARCHITECTURE.md#грамматика-запросов).

По умолчанию выводится до десяти документов. Чтобы получить все совпадения в индексе из 50 тысяч
документов:

```bash
./build/search_engine search \
  --index data/index-50k \
  --query 'machine AND learning' \
  --top-k 50000 > results.jsonl
```

Выдача имеет формат JSONL: одна строка JSON на документ с полями `internal_id`, `docid`, `title`,
`url`, `snippet`. Сначала в памяти собираются номера найденных документов — не больше `top-k`, —
затем для них читаются заголовки, адреса и сохранённые фрагменты текста. Диагностика идёт в поток
ошибок stderr, поэтому перенаправление обычного вывода stdout сохраняет только результаты. Документы
упорядочены по внутренним номерам, а не по смысловой близости к запросу.

`--advance binary` использует экспоненциальный поиск и бинарный поиск внутри найденного диапазона.
Это режим по умолчанию. `--advance sequential` просматривает записи последовательно. Оба режима
должны возвращать одинаковые документы.

## Остальные команды

| Команда                                          | Назначение                                           |
| ------------------------------------------------ | ---------------------------------------------------- |
| `serve`                                          | Запуск [веб-интерфейса](WEB.md)                      |
| `stats --index DIR`                              | Статистика готового индекса                          |
| `validate --index DIR`                           | Проверка всех файлов индекса и сведений о документах |
| `generate --output FILE --documents N --seed 42` | Создание тестового корпуса с повторяемым содержимым  |
| `benchmark`                                      | Измерение запросов из файла                          |
| `benchmark-intersection`                         | Сравнение пересечений искусственных списков          |

Статистика и проверка:

```bash
./build/search_engine stats --index data/index-50k
./build/search_engine validate --index data/index-50k
```

Полная проверка проходит по всем записям. Для большого индекса она занимает время и не требуется
перед каждым запросом.

## Измерения

Файл запросов содержит по одному выражению на строку:

```bash
./build/search_engine benchmark \
  --index data/index-50k \
  --queries benchmarks/msmarco_queries.txt \
  --repeats 100 --top-k 10 --advance binary
./build/search_engine benchmark-intersection
```

Для серий экспериментов предусмотрены `scripts/run_benchmarks.sh` и `scripts/run_msmarco.sh`. Они
сохраняют JSON и вывод `/usr/bin/time -v`. Существующие индексы пропускаются; чтобы заново измерить
построение, измените второй аргумент сценария: он задаёт общее начало имён создаваемых каталогов.

Измеряемое время запроса включает разбор выражения, подготовку операций и получение внутренних
номеров документов. Открытие индекса, чтение заголовков и адресов и печать результатов в этот
показатель не входят. Методика и полученные числа приведены в [отчёте](../reports/RESULTS.md).

## Проверки

Запустить тесты после сборки:

```bash
ctest --test-dir build --output-on-failure
```

Они проверяют построение индекса, поиск, повторное открытие файлов и команды программы. Проверки
веб-сервера добавляются при наличии `curl` и `jq`; для запуска и остановки процессов нужны также
`ss` и `flock`.

Для поиска ошибок памяти и недопустимых операций C++:

```bash
cmake -S . -B build-sanitize -DCMAKE_BUILD_TYPE=Debug -DSEARCH_SANITIZERS=ON
cmake --build build-sanitize -j 4
ctest --test-dir build-sanitize --output-on-failure
```

Проверить выбор фрагментов и подсветку слов:

```bash
node --test tests/text.test.cjs
```

Проверить интерфейс в браузере:

```bash
SEARCH_WEB_URL=http://127.0.0.1:8080 node tests/web_browser.cjs
```

Для последней команды нужны Playwright с Chromium, запущенный сервер и индексы `index-full` и
`index-50k-snippets`. Дополнительный `SEARCH_FIXTURE_URL` включает проверку на отдельном тестовом
корпусе. Для обычного запуска поисковика Node.js не нужен.

Проверить или применить оформление C++:

```bash
sudo apt-get install clang-format-18
./scripts/format_cpp.sh --check
./scripts/format_cpp.sh --write
```

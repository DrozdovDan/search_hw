# Ключевые участки кода индекса

Основная реализация находится в [src/index.cpp](../src/index.cpp), объявления классов и методов — в
[include/search/index.hpp](../include/search/index.hpp). Ниже собраны участки, которые стоит
прочитать в первую очередь. В примерах оставлены основные строки; полные методы доступны по ссылкам.

Терм — слово после обработки текста. Структура `Posting` хранит номер документа с этим словом и
признаки полей. Такие записи образуют отсортированный список документов. Сегмент — временный индекс
для части корпуса.

## 1. Пять байт на запись

[SegmentWriter::posting()](../src/index.cpp#L244):

```cpp
void posting(Posting posting) {
    write_u32(postings_, posting.doc_id);
    postings_.put(static_cast<char>(posting.fields));
    ++posting_count;
}
```

На диске номер документа занимает четыре байта, маска полей — один. Структуру `Posting` нельзя
просто записать через `sizeof`: компилятор может добавить выравнивающие байты. Число записывается
явно, младшим байтом вперёд. Такой порядок называется little-endian.

Повторы слова внутри документа удаляет `TextAnalyzer::analyze()`. Если слово есть в title и body,
сохраняется одна запись с маской `1 | 4`.

## 2. Параллельный анализ, номера документов по порядку

[DocumentPipeline::next()](../src/index.cpp#L518) забирает результаты в порядке поступления
документов:

```cpp
auto pending = std::move(pending_.front());
pending_.pop_front();
queued_bytes_ -= pending.bytes;
lock.unlock();
condition_.notify_all();
return pending.result.get();
```

Документы анализируются одновременно, но основной поток забирает их в порядке чтения. Для каждого
задания есть `future` — объект, через который можно получить результат после завершения работы.
Вызов `get()` дожидается очередного документа, если тот ещё обрабатывается. Если при обработке
произошла ошибка, её получает основной поток.

Затем [IndexBuilder](../src/index.cpp#L737) назначает внутренний номер и добавляет записи в списки:

```cpp
auto id = static_cast<uint32_t>(stats.documents);
// Для каждого уникального терма текущего документа:
target->push_back({id, fields});
```

Следующий документ получает больший ID. Поэтому номера в каждом списке сразу идут строго по
возрастанию; сортировать номера после наполнения не требуется. Ограниченная очередь также не даёт
быстрому читателю накопить весь корпус в памяти.

## 3. Проверка свободной памяти до добавления документа

[IndexBuilder::build()](../src/index.cpp#L719):

```cpp
auto [needed, next_size] = required(analyzed);
if (resource.used + needed > resource.limit()) {
    flush();
    std::tie(needed, next_size) = required(analyzed);
}
```

`required()` оценивает новые строки, узлы таблицы и рост векторов до изменения сегмента. Если места
недостаточно, текущий сегмент записывается, и оценка повторяется уже для пустой таблицы. Один
документ между сегментами не делится.

Повторная оценка нужна ещё и потому, что `required()` запоминает адреса уже существующих списков.
После `flush()` эти адреса недействительны.

[BudgetResource](../src/index.cpp#L181) считает фактически выделенные байты и не позволяет
структурам сегмента превысить предел — 75% `--memory-limit-mb`. Память остальных частей программы в
этот счётчик не входит. Если один документ не помещается в пустой сегмент, построение завершается с
сообщением об увеличении памяти; готовый каталог индекса при этом не создаётся.

## 4. Перед записью сегмента сортируются указатели

[Лямбда flush()](../src/index.cpp#L654):

```cpp
std::vector<const TermMap::value_type*> sorted;
sorted.reserve(terms.size());
for (const auto& entry : terms)
    sorted.push_back(&entry);
std::sort(sorted.begin(), sorted.end(), [](const auto* a, const auto* b) {
    return a->first < b->first;
});
```

Во время наполнения удобна хеш-таблица: по терму быстро находится его список. Для записи нужен
отсортированный словарь. Поэтому сортируется небольшой массив указателей на элементы таблицы, а
строки и длинные списки документов остаются на месте.

`SegmentWriter` записывает слова по порядку, затем таблица освобождается. Обмен с пустой таблицей
через `swap()` освобождает также её внутренний массив, который обычный `clear()` мог бы сохранить.

## 5. Слияние использует порядок диапазонов

[merge_segments()](../src/index.cpp#L308) хранит текущее слово каждого сегмента в очереди с
приоритетом. Она позволяет быстро выбрать минимальное слово. Когда найдены все сегменты с этим
словом, номера сегментов сортируются:

```cpp
std::sort(matches.begin(), matches.end());
writer.term(term, df);
for (size_t index : matches) {
    auto& reader = *readers[index];
    // Проверка позиции и обновление читателя находятся в полном исходнике.
    writer.copy(reader.postings, reader.info.df);
}
```

Сегменты соответствуют последовательным непересекающимся диапазонам ID. Поэтому `[2, 7]` из первого
и `[1003, 1100]` из второго можно просто соединить: получится `[2, 7, 1003, 1100]`. Перенумерация и
повторная сортировка всех номеров документов не нужны.

Порядок `matches` важен: сегменты с одинаковым словом могут выбираться из очереди в любом порядке.
Ограничение `merge-fan-in` задаёт размер группы, а большие наборы сегментов проходят несколько
слияний. Для копирования блоков данных используется один и тот же буфер размером 128 КиБ.

## 6. Таблица смещений даёт доступ к записям разной длины

[TermDictionary::at()](../src/index.cpp#L569):

```cpp
uint64_t offset = load_u64(offsets_.at(ordinal * 8, 8));
uint32_t length = load_u32(data_.at(offset, 4));
offset += 4;
std::string_view term(data_.at(offset, length), length);
```

Слова имеют разную длину, поэтому их адрес нельзя вычислить как номер, умноженный на постоянный
размер записи. В `terms.offsets` лежат восьмибайтовые смещения, а сами слова находятся в
`terms.data`.

[find()](../src/index.cpp#L582) использует эту таблицу для бинарного поиска. Файлы отображены через
`mmap`: доступ к словарю идёт через адреса памяти, связанные с его файлом, без отдельной полной
копии. `string_view` ссылается на эти байты и остаётся доступным, пока открыт словарь.

## 7. advance() сначала ограничивает диапазон

[advance_position()](../src/index.cpp#L35) — общий алгоритм для вектора в тестах и дискового списка.
Расстояние от текущей позиции удваивается:

```cpp
uint64_t low = position + 1, step = 1;
while (step < size - position && less(position + step)) {
    low = position + step + 1;
    // В исходнике перед удвоением проверяется граница и переполнение.
    step *= 2;
}
```

В найденном диапазоне бинарный поиск определяет первую позицию с номером не меньше требуемого:

```cpp
while (low < high) {
    const auto middle = low + (high - low) / 2;
    if (less(middle))
        low = middle + 1;
    else
        high = middle;
}
```

В списке `[2, 7, 15, 40]` вызов `advance(12)` приводит курсор к документу 15. Переход выполняется
только вперёд. Число сравнений зависит от расстояния до ответа как `O(log(d + 1))`; это не обещание
такого же времени дискового чтения. Фильтр поля может дополнительно пропускать записи линейно.

## 8. Готовый индекс появляется после завершения записи

[Конец IndexBuilder::build()](../src/index.cpp#L824):

```cpp
output.close();
check_stream(output, "Сохранение манифеста");
// Все файлы уже записаны, каталог work ещё временный.
stats.index_bytes = directory_size(work);
fs::rename(work, options.output);
```

Построение идёт в соседнем каталоге `OUTPUT.building-PID`. Файл `manifest.json` с описанием индекса
создаётся последним, затем временный каталог переименовывается в конечный. При обычном исключении
рабочий каталог удаляется. После аварийного завершения он может остаться; вызов `fsync()` для
обязательной записи данных на устройство не реализован.

[validate_index()](../src/index.cpp#L840) отдельно проверяет словарь, списки документов и
сохранённые сведения о документах. Обычное открытие проверяет версии и размеры; полный проход не
добавляется к каждому поисковому запросу.

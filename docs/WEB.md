# Веб-интерфейс

Браузерный интерфейс использует тот же поисковый код, что программа для командной строки. Он
позволяет менять индекс, задавать булевы условия, листать выдачу и читать исходные поля документа.

## Запуск

Для полного индекса:

```bash
./scripts/web_server.sh start
./scripts/web_server.sh status
```

Для другого индекса по умолчанию:

```bash
SEARCH_INDEX=data/index-50k ./scripts/web_server.sh start
```

Сценарий управляет одним фоновым процессом. Перед сменой его порта или индекса по умолчанию
остановите текущий процесс:

```bash
./scripts/web_server.sh stop
SEARCH_PORT=8090 SEARCH_INDEX=data/index-50k ./scripts/web_server.sh start
```

Он продолжает работать после закрытия SSH. После перезагрузки сервера требуется новый запуск. Номер
процесса (PID) сохраняется в `data/web-server.pid`, сообщения сервера — в `data/web-server.log`.

Для запуска в терминале с выходом по Ctrl+C:

```bash
./scripts/run_web.sh
```

Для прямой настройки сервера:

```bash
./build/search_engine serve \
  --index data/index-full \
  --host 0.0.0.0 \
  --port 8080 \
  --workers 4 \
  --web-root web \
  --cache-dir data/web-cache \
  --indexes-root data
```

`serve` по умолчанию принимает подключения только с самого сервера, на адресе `127.0.0.1`. Сценарии
запуска задают `0.0.0.0`, чтобы принимать подключения и с других компьютеров. Страница доступна по
`http://<адрес-сервера>:8080`.

## Доступ через SSH

Если порт не доступен напрямую, выполните на своём компьютере:

```bash
ssh -N -L 8090:127.0.0.1:8080 user@server
```

Оставьте SSH открытым и перейдите на `http://localhost:8090`. Здесь 8090 — порт на вашем компьютере,
8080 — порт сервера.

## Поиск и чтение

В поле запроса вводится такое же выражение, как в командной строке:

```text
machine ANDNOT (python OR model)
title:python AND body:learning
```

На странице можно выбрать индекс, размер выдачи и алгоритм `advance()`. В список при запуске сервера
попадают совместимые каталоги `index-*` и `my-index-*` из `--indexes-root`, а также индекс,
указанный явно. Чтобы появился новый каталог, перезапустите сервер.

При выборе карточки открываются заголовок `title`, подзаголовки `headings` и основной текст `body`.
Контекстный фрагмент выбирается вокруг слов запроса, даже если индекс построен с
`--snippet-bytes 0`. Обычно он берётся из основного текста; если нужного слова там нет, проверяются
подзаголовки и заголовок. Метка BODY, HEADINGS или TITLE указывает источник.

При выборе фрагмента предпочтение получает участок, где рядом находятся разные слова запроса. Выбор
фрагмента не меняет порядок документов в выдаче: они по-прежнему идут по внутренним номерам. Видимые
карточки получают фрагменты постепенно. Выбранная карточка и панель текста используют одну загрузку;
в браузере сохраняются копии недавно прочитанных документов — не больше 12 записей и примерно 24 МиБ
их текста. При заполнении этого кэша удаляется копия, к которой дольше всего не обращались.

Слова запроса выделяются как целые слова: `model` не подсвечивается внутри `models`. Кнопка «К
совпадениям» и стрелки перемещают просмотр по полному тексту. Текущее совпадение выделено оранжевым,
остальные — зелёным. Смена запроса отменяет устаревшие загрузки. Клавиша `/` переводит фокус в поле
поиска.

Ссылка на страницу сохраняет запрос и выбранные параметры в URL.

## Откуда берётся полный текст

Поисковый индекс хранит сведения для выдачи: исходный идентификатор, заголовок, адрес и, при
необходимости, начало текста. Полные поля читаются из исходного корпуса, путь к которому записан в
`manifest.json` — файле описания индекса. Текущие сайты по URL не скачиваются. Их содержимое может
отличаться от записи MS MARCO.

В официальном корпусе `docid` содержит номер gzip-файла и смещение строки документа в распакованных
данных. Сервер находит этот файл по таблице tar и распаковывает его до нужной строки. После чтения
проверяется совпадение `docid`. Документ ближе к концу сжатого файла при первом обращении может
загружаться несколько секунд.

Прочитанные документы сохраняются в `data/web-cache`. Это кэш: при следующем обращении берётся уже
сохранённая копия, повторная распаковка не нужна. При выборе кэша проверяются путь, размер и время
изменения файла корпуса. Для пользовательского JSONL/gzip или каталога используется чтение через
`CorpusReader` до нужного docid с тем же кэшированием.

Содержимое документа добавляется на страницу как текст. Даже если в нём есть HTML-теги или
JavaScript, они не выполняются. Ссылки допускаются только с протоколами HTTP и HTTPS.

## Ошибки запуска

`Address already in use` означает, что порт занят. Сначала проверьте:

```bash
./scripts/web_server.sh status
```

Если это уже работающий интерфейс, откройте его адрес. Для перезапуска используйте `stop`, затем
`start`. Повторный `start` сам по себе второй процесс не создаёт. Если файл с номером процесса
потерян или устарел, сценарий ищет процесс, занявший нужный порт, и проверяет, что это наш сервер.
Блокировка `flock` не позволяет двум командам управления выполняться одновременно. Номер нового
процесса записывается в основной файл после того, как сервер занял порт и начал отвечать на
HTTP-запросы. Для этого нужны `ss` из iproute2 и `flock` из util-linux.

Если полные поля не загружаются, проверьте доступность исходного корпуса, указанного в
`manifest.json`. Поиск и показ заголовков с адресами могут работать и без этого файла, но
восстановить из них полный текст нельзя.

## Проверки

Интерфейс написан на HTML/CSS/JS. Его файлы не требуют отдельной сборки и не загружаются со
сторонних серверов. Сервер работает на C++; Node.js нужен только для дополнительных проверок.
Команды проверки API, текстового модуля и браузерного сценария приведены в
[руководстве разработчика](DEVELOPMENT.md).

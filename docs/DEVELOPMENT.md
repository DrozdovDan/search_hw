# Разработка и проверки

Объявления классов и функций находятся в `include/search/`, реализации — в `src/`. Файл
`src/main.cpp` разбирает аргументы командной строки. Поисковую библиотеку можно использовать
отдельно от терминала; веб-сервер вызывает тот же код разбора и выполнения запросов.

## Оформление

Идентификаторы пишутся по-английски, комментарии и документация — по-русски. Комментарии объясняют
ограничения, кто отвечает за освобождение памяти и почему выбрано такое решение. Повторять словами
очевидное присваивание не требуется.

C++ оформляется clang-format 18 по настройкам `.clang-format`: отступ четыре пробела, ширина строки
110, короткие обращения к полям могут оставаться в одну строку. Составные операции и длинные условия
разбиваются на отдельные строки. Порядок директив `#include` и текст комментариев программа
форматирования сохраняет.

```bash
sudo apt-get install clang-format-18
./scripts/format_cpp.sh --check
./scripts/format_cpp.sh --write
```

Проверка без аргументов равнозначна `--check`. Путь к другой установке можно задать через
`CLANG_FORMAT`. Сценарий обрабатывает только собственные `.cpp` и `.hpp` из `src/`, `include/`,
`tests/`; `third_party/` и результаты сборки исключены. `.editorconfig` задаёт кодировку UTF-8,
окончания строк LF и отступы для редактора.

При изменении поведения обновляйте пример или раздел документации, который его описывает. Если
меняется формат записей в файлах или правила обработки слов, нужно также изменить соответствующую
версию в `manifest.json`, который описывает индекс.

## Сборка

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j 8
ctest --test-dir build --output-on-failure
```

Для поиска ошибок памяти и недопустимых операций C++ используются AddressSanitizer и
UndefinedBehaviorSanitizer (ASan/UBSan). Сборка с этими проверками:

```bash
cmake -S . -B build-sanitize -DCMAKE_BUILD_TYPE=Debug -DSEARCH_SANITIZERS=ON
cmake --build build-sanitize -j 4
ctest --test-dir build-sanitize --output-on-failure
```

## Что проверяют тесты

| Набор           | Проверки                                                                                                        |
| --------------- | --------------------------------------------------------------------------------------------------------------- |
| `search_tests`  | Обработка Unicode, запись и чтение данных, обход списков, разбор запросов, булевы операции и построение индекса |
| `cli_restart`   | Построение и поиск в отдельных процессах, интерактивная сессия, ошибки аргументов                               |
| `web_api`       | HTTP-запросы, переход между страницами выдачи, полные поля и чтение документов из tar/gzip по смещению          |
| `web_lifecycle` | Повторный и одновременный запуск, восстановление номера процесса, остановка сервера                             |

В тестах C++ результаты для случайно созданных списков сравниваются с операциями стандартной
библиотеки над множествами. Случайные запросы проверяются независимым способом: условие вычисляется
для каждого документа. При построении проверяются запись сегмента из-за нехватки памяти, несколько
проходов объединения, пустой корпус и одинаковые файлы при разном числе рабочих потоков и сегментов.

Веб-тесты добавляются при наличии `curl` и `jq`; для управления процессами нужны также `flock` и
`ss`. На Ubuntu они входят в util-linux и iproute2. Тесты запускают свои серверы на отдельных
портах.

## Проверки интерфейса

Серверу не нужен Node.js. Он используется только для дополнительных проверок текста и браузерного
сценария.

Контекстные фрагменты и Unicode-подсветка:

```bash
node --test tests/text.test.cjs
```

Браузерный сценарий требует установленного Playwright с Chromium и работающего сервера:

```bash
SEARCH_WEB_URL=http://127.0.0.1:8080 node tests/web_browser.cjs
```

Этот сценарий рассчитан на индексы `index-full` и `index-50k-snippets`, с которыми выполнялась
проверка проекта. Он проверяет реальные документы, переход между совпадениями и страницами выдачи,
смену алгоритма и отображение на узком экране. Дополнительный `SEARCH_FIXTURE_URL` включает сценарий
с отдельным тестовым корпусом: совпадение далеко от начала текста, HTML как данные и повторное
использование загрузки. Снимки сохраняются в `reports/web-{home,desktop,mobile}.png`.

## Данные и результаты

Корпуса, индексы, рабочие каталоги и сборки исключены через `.gitignore`. Готовый индекс хранится в
своём каталоге. Для эксперимента с другим форматом или параметрами создавайте индекс в новом
каталоге.

В `reports/` лежат зафиксированные результаты запусков. Старые числа не следует заменять прогнозами
или результатами другого набора запросов. Для нового измерения сохраняйте отдельный отчёт с
параметрами и методикой.

При правках документации и оформления достаточно проверки ссылок и обычной сборки. Повторное
построение полного MS MARCO нужно, когда изменение затрагивает сам индекс или когда требуется новое
измерение производительности.

# Архитектура и формат индекса

Здесь описаны хранение данных, построение индекса и выполнение запросов. Для первого знакомства
подойдёт [разбор на примере](HOW_IT_WORKS.md); для чтения исходников —
[ключевые участки кода](INDEX_GUIDE.md).

В тексте используются три понятия. Терм — слово после обработки текста, например приведения букв к
нижнему регистру. Список документов содержит номера документов, где встречается этот терм. Сегмент —
временный индекс для части корпуса; несколько сегментов затем объединяются в один индекс.

## Чтение и обработка документов

Один поток последовательно читает корпус. Несколько рабочих потоков выделяют слова из документов; их
число задаётся параметром `--threads`. Основной поток получает результаты, назначает внутренние
номера документов и добавляет записи в индекс. Эти этапы могут выполняться одновременно.

Результаты анализа принимаются в порядке чтения корпуса. Поэтому изменение числа рабочих потоков не
меняет номера документов и содержимое файлов индекса. Заголовки, URL и другие сведения для выдачи
сразу записываются на диск.

Ошибка любого этапа передаётся основному потоку. Если основной поток прекращает работу, он подаёт
сигнал завершения. Поток чтения выходит из ожидания свободного места в очереди и останавливается;
основной поток дожидается этой остановки.

## Память и запись сегментов

Слова текущего сегмента хранятся в таблице `term → vector<Posting>`. Для каждого слова есть растущий
список номеров документов и признаков полей. Анализатор заранее удаляет повторы слова внутри одного
документа. Документы добавляются по порядку, поэтому номера в списках сразу возрастают.

В таблице используются контейнеры `std::pmr`. Они передают запросы на выделение и освобождение
памяти объекту `BudgetResource`, который считает занятые байты и проверяет предел.

Параметр `--memory-limit-mb` задаётся в МиБ, минимум 8. Из этого объёма 75% выделено структурам
сегмента: строкам, спискам документов и внутренним массивам хеш-таблицы. До добавления очередного
документа оценивается, сколько памяти потребуется. При росте контейнера могут кратковременно
существовать старый и новый массивы; оценка учитывает это. Если места не хватает, сегмент
записывается на диск, а его память освобождается. Документ, который не помещается даже в пустой
сегмент, приводит к ошибке с предложением увеличить `--memory-limit-mb`.

Оставшаяся четверть служит запасом для сортировки, анализа и буферов. **Параметр не ограничивает всю
память процесса.** Дополнительная память нужна разбору JSON, рабочим потокам, библиотеке ICU и
другим служебным данным. Показатель RSS отражает фактический объём оперативной памяти процесса; его
максимум и максимум учтённых `BudgetResource` байтов выводятся отдельно.

Очередь ожидающих обработки документов ограничена и по числу записей, и по размеру исходного текста.
В ней допускается до восьми документов на рабочий поток. Для текста берётся меньший из двух
пределов: 8 МиБ или одна восьмая заданного объёма памяти. Один документ может быть больше этого
предела; тогда он проходит только при пустой очереди. Длина строки JSONL ограничена 64 МиБ.

Перед записью сегмента сортируются указатели на слова. Длинные списки номеров при этом не копируются
и не сортируются заново.

## Объединение сегментов

Параметр `--merge-fan-in` задаёт, сколько сегментов можно объединять одновременно: от 2 до 64, по
умолчанию 16. Если сегментов больше, объединение выполняется за несколько проходов. В памяти
хранятся текущее слово каждого сегмента, очередь для выбора минимального слова и буфер копирования.
Для группы открыто примерно `2 × fan_in + 3` файлов; число всех сегментов на это не влияет. Список
путей занимает память, пропорциональную общему числу сегментов.

Сегменты охватывают последовательные непересекающиеся диапазоны номеров документов. Поэтому списки
одного слова можно дописывать друг за другом в порядке сегментов: номера уже будут возрастать.
Перенумерация не нужна. Исходные файлы группы удаляются после успешной записи объединённого
сегмента.

`--segment-docs N` дополнительно ограничивает число документов в сегменте. По умолчанию этот предел
отключён, и размер сегмента определяется доступной памятью.

При записи программа ведёт счётчики байтов вместо вызова `tellp()` для каждой записи. Во время
объединения файлы каждого сегмента читаются последовательно. Ожидаемое смещение проверяется по
словарю, но `seekg()` между соседними списками не вызывается. Это позволяет читать и записывать
данные крупными блоками, даже когда отдельных списков очень много.

Построение идёт в соседнем временном каталоге `OUTPUT.building-PID`. Файл `manifest.json` с
описанием готового индекса записывается последним, затем временный каталог переименовывается в
`OUTPUT`. При обычной ошибке временный каталог удаляется; после аварийного завершения он может
остаться. Вызов `fsync()` для обязательной записи данных на устройство не реализован.

## Формат индекса, версия 1

Числа записываются младшим байтом вперёд — это порядок little-endian. Дополнительные байты, которые
компилятор может вставлять между полями структуры C++, в файл не попадают. `u8`, `u32` и `u64`
обозначают беззнаковые целые размером 1, 4 и 8 байт.

Внутренний номер документа `doc_id` занимает 32 бита и начинается с нуля. Число документов
ограничено `2^32 − 1`. Смещения в файлах занимают 64 бита. Версии формата и обработки текста
проверяются по `manifest.json`.

| Файл                | Содержимое                                                                                          |
| ------------------- | --------------------------------------------------------------------------------------------------- |
| `manifest.json`     | Версии, количество документов, слов, записей списков и сегментов; параметры и результаты построения |
| `terms.offsets`     | По одному смещению u64 в `terms.data` на слово; слова упорядочены по байтам UTF-8                   |
| `terms.data`        | Записи `[u32 длина][байты терма][u64 смещение postings][u64 df]`                                    |
| `postings.data`     | Для каждого слова подряд `df` записей `[u32 doc_id][u8 поля]`, по 5 байт                            |
| `documents.offsets` | По одному смещению u64 на документ; оно указывает на запись в `documents.data`                      |
| `documents.data`    | Четыре строки: исходный docid, title, url, snippet; каждая `[u32 длина][байты UTF-8]`               |

Маска полей состоит из независимых битов: `title=1`, `headings=2`, `body=4`. Например, значение 5
означает заголовок и основной текст. В списке слова каждый документ встречается один раз. `df` —
количество документов в этом списке независимо от поля. Число повторов слова, его позиции и сжатие
списков не сохраняются.

Файлы открываются только для чтения через `mmap`: операционная система предоставляет доступ к байтам
файла через адреса памяти и подгружает нужные страницы. Отдельная копия всего индекса не создаётся.
Бинарный поиск по словарю выполняет `O(log V)` сравнений слов.

Итератор списка хранит `shared_ptr` на отображённый файл: пока хотя бы один итератор пользуется
файлом, отображение остаётся открытым. При обычном запуске проверяются размеры, версии и границы
прочитанных записей. Команда `validate` отдельно проходит по всем данным: проверяет порядок слов и
номеров, длины списков, смещения, маски полей и сведения о документах. Эта проверка не вычисляет
контрольную сумму файлов.

## Токенизация

Токенизация — выделение слов из текста. Библиотека ICU читает символы UTF-8, объединяет буквы и
цифры в слова и приводит каждую букву к нижнему регистру. Отдельные знаки ударения и другие
диакритические знаки могут продолжать начатое слово. Пробелы, пунктуация, дефисы и подчёркивания
разделяют слова. Некорректный UTF-8 приводит к ошибке.

Обрабатываются `title`, `headings` и `body`. URL сохраняется для выдачи, но его слова не
индексируются. Стоп-слова не удаляются. Разные формы слова не приводятся к общей основе: `machine` и
`machines` остаются разными словами.

Программа также не объединяет все возможные Unicode-представления одного написания. Например,
`Straße` и `STRASSE` различаются; буква с отдельным знаком ударения может отличаться от одного
готового символа с этим ударением. Дополнительные преобразования Unicode здесь не выполняются:
`case folding` позволяет приравнивать больше вариантов регистра букв, а `NFC`/`NFKC` приводят разные
записи символов к общей форме. При построении и поиске следует использовать одну версию ICU/Unicode.

## Грамматика запросов

```text
query      := union
union      := difference { "OR" difference }
difference := primary { ("AND" | "ANDNOT") primary }
primary    := term | "(" query ")"
term       := [ ("title" | "headings" | "body") ":" ] word
```

`AND` и `ANDNOT` имеют одинаковый приоритет, выше `OR`. Операции одного приоритета группируются
слева направо. Операторы пишутся заглавными ASCII-буквами. Пробел перед скобкой не обязателен. Между
двумя словами нужна операция; фразы и отдельный унарный `NOT` не поддерживаются.

После обработки одна часть запроса должна давать ровно одно слово: `word,` допустимо, а `foo-bar`
требует явного `foo AND bar`. Поле задаётся для отдельного слова, например
`title:machine AND body:learning`. Строчное `and` ищется как обычное слово.

Парсер — часть программы, которая строит дерево запроса, — использует алгоритм сортировочной станции
(shunting-yard): он хранит операции и готовые подвыражения в двух списках, откуда последняя
добавленная запись забирается первой. Такие списки называются стеками. Поэтому каждая пара скобок не
требует отдельного рекурсивного вызова. Ошибки скобок, пропущенные слова или операции и неизвестные
поля приводят к сообщению с позицией ошибки.

Запрос ограничен 1 МиБ текста и 2048 словами и операторами в сумме. Сами скобки не входят в этот
счётчик, но входят в размер текста. Выполнение и удаление полученного дерева используют рекурсивные
вызовы для вложенных операций.

## Исполнение и сложность

`PostingIterator` хранит текущую позицию в возрастающем списке номеров. Его методы — `valid()`,
`doc_id()`, `next()` и `advance(target)`. Последний переходит к первому номеру не меньше `target` и
не возвращается назад. Когда список закончился, `next()` и `advance()` оставляют его в этом
состоянии, а `doc_id()` сообщает об ошибке. При поиске по полю записи проверяются по маске.

Два режима `--advance`:

- `sequential` просматривает пропускаемые записи по одной: `O(d + 1)` сравнений для расстояния d;
- `binary` сначала проверяет расстояния 1, 2, 4, 8 и далее от текущей позиции, затем бинарным
  поиском находит первый подходящий номер в полученном диапазоне. Число сравнений — `O(log(d + 1))`
  для положительного d; остановка на текущей записи требует постоянного числа действий.

Запись фиксированного размера позволяет обращаться к любой позиции по формуле
`начало списка + номер записи × 5`. Отдельная таблица для пропуска участков не нужна. Если данные
ещё не находятся в оперативной памяти, чтение несмежных участков может оказаться дороже
последовательного прохода. Фильтр поля после перехода может дополнительно просмотреть несколько
записей или остаток списка.

`AND` подводит меньший текущий номер к большему, пока они не совпадут. `OR` возвращает меньший номер
и сдвигает оба списка при совпадении. `ANDNOT` берёт номера слева и исключает встречающиеся справа.
Полные массивы промежуточных результатов не создаются: каждая операция выдаёт номера по одному.

Для `AND` и `OR` стороны могут меняться местами по оценке количества результатов. Для `ANDNOT`
порядок сохраняется. Обход останавливается после получения нужного числа документов; память итоговой
выдачи составляет `O(top_k)`.

Для оценок ниже V — количество слов в словаре, P — число записей списков, S — число сегментов, F —
число одновременно объединяемых сегментов, m и n — длины двух списков, T — число слов документа до
удаления повторов, U — число разных слов в нём.

- Анализ документа: `O(T log T)` на сортировку и `O(T)` памяти. Добавление U слов в хеш-таблицу в
  среднем занимает `O(U)`; при специально подобранных совпадениях хешей эта оценка не гарантируется.
- Запись сегмента: `O(V_seg log V_seg + P_seg)`. В памяти находятся данные одного сегмента.
- Один проход объединения: `O(P + E log F)`, где E — число словарных записей всех входящих
  сегментов. Помимо небольшого буфера нужны текущие слова и записи очереди для F сегментов.
  Максимальное число проходов — `ceil(log_F S)` при S > 1; это округление логарифма вверх.
- Последовательные `AND`, `OR`, `ANDNOT`: `O(m + n)`, дополнительная память — `O(1)` на одну
  операцию над двумя списками. Ускоренные переходы особенно полезны при большой разнице длин.
- Чтение сведений о документе: `O(1)` для поиска смещения плюс время на чтение строк. Полная
  проверка: `O(V + P + число документов + размер прочитанных метаданных)`.
